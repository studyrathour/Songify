1. EXECIVE SUMMARY
================================================================================

Songify is a comprehensive Android music streaming application that leverages 
the official YouTube Data API and InnerTube protocol to provide ad-free music 
streaming, offline playback, and synchronized lyrics. This document provides a 
complete specification for building a production-ready music application with 
modern Material You design, robust playback capabilities, and full offline support.

The application is designed to deliver a premium user experience with features 
including background playback, Android Auto support, home screen widgets, Discord 
Rich Presence integration, Last.fm scrobbling, and intelligent queue management 
with smart recommendations. All streaming is performed through official YouTube 
APIs ensuring compliance and reliability.

7. CORE FEATURES IMPLEMENTATION
================================================================================

7.1 YouTube Integration (InnerTube)
-----------------------------------
The app uses the InnerTube protocol to communicate with YouTube's internal API.

API Configuration:
  - Base URL: https://music.youtube.com/youtubei/v1/
  - Clients: WEB_REMIX (YouTube Music), WEB (YouTube)
  - Content-Type: application/json
  - Required Headers:
    - X-Goog-Api-Format-Version: 1
    - X-YouTube-Client-Name: [clientId]
    - X-YouTube-Client-Version: [clientVersion]
    - X-Origin: https://music.youtube.com
    - Referer: https://music.youtube.com/

Authentication:
  - SAPISID cookie-based authentication
  - SAPISIDHASH header for authenticated requests
  - Formula: SHA1(currentTime + SAPISID + ORIGIN)

Key Endpoints:
  - player: Get stream URLs and playback info
  - browse: Browse content (home, albums, artists)
  - search: Search for songs, albums, artists
  - next: Get next songs in queue
  - get_queue: Get full queue from playlist
  - get_transcript: Get video subtitles/lyrics

Stream URL Handling:
  - Parse adaptive formats from player response
  - Handle signature timestamps for protected content
  - Support quality selection (High/Medium/Low)
  - Cache stream URLs with expiry tracking

7.2 Music Playback Service
--------------------------
The MusicService extends MediaLibraryService for background playback.

ExoPlayer Configuration:
  - Wake lock: WAKE_MODE_NETWORK
  - Audio attributes: USAGE_MEDIA, CONTENT_TYPE_MUSIC
  - Seek increments: 5000ms (5 seconds)
  - Skip silence support (configurable)

Audio Focus:
  - AudioFocusRequest with AUDIOFOCUS_GAIN
  - Handle focus loss: pause playback
  - Handle focus loss transient: pause playback
  - Handle ducking: reduce volume to 20%

Media Session:
  - MediaLibrarySession with custom commands:
    - CommandToggleLike
    - CommandToggleRepeatMode
    - CommandToggleShuffle
    - CommandToggleStartRadio
  - Custom notification layout with like, repeat, shuffle buttons

Persistent Queue:
  - Save queue to disk on app background
  - Restore queue on app start
  - Periodic saves (30 seconds interval)
  - More frequent saves when playing (10 seconds)

Sleep Timer:
  - Configurable duration (5-120 minutes)
  - End of song option
  - Proper cleanup on timer expiry

Loudness Normalization:
  - LoudnessEnhancer for consistent volume
  - Parse loudnessDb from format entity
  - Apply gain based on perceived loudness

7.3 Download Manager
--------------------
Offline playback supported through ExoPlayer's DownloadManager.

Configuration:
  - Max parallel downloads: 3
  - Download cache: Separate from playback cache
  - Notification channel: "download_channel"

Data Source Factory:
  - ResolvingDataSource for URL resolution
  - Check cache before fetching
  - Handle expired stream URLs
  - Store format info in database

Download States:
  - STATE_COMPLETED: Mark isDownloaded = true
  - STATE_FAILED: Mark isDownloaded = false
  - STATE_STOPPED: Mark isDownloaded = false
  - STATE_REMOVING: Mark isDownloaded = false

Database Tracking:
  - isDownloaded: Boolean flag
  - dateDownload: LocalDateTime
  - FormatEntity: itag, bitrate, sampleRate, contentLength

7.4 Lyrics System
-----------------
Multiple lyrics providers with concurrent fetching and fallback priority.

Provider Priority (configurable):
  1. Better Lyrics - Time-synced with word-by-word highlighting
  2. SimpMusic - Community-sourced synced lyrics
  3. LRC Lib - Open-source lyrics database
  4. KuGou - Chinese/Japanese lyrics provider
  5. YouTube Subtitles - Caption-based fallback
  6. YouTube Lyrics - YouTube Music's built-in lyrics

Lyrics Format:
  - LRC format: [mm:ss.xx] lyrics text
  - Synced: Scrollable with current line highlight
  - Plain text: Static display

Performance:
  - LRU cache (size: 3)
  - Concurrent provider fetching
  - "Race" logic for fastest synced lyrics
  - Network availability check before fetching

8. DATABASE SCHEMA
================================================================================

Room database with the following entities (Version 28):

SongEntity
----------
- id: String (PRIMARY KEY) - YouTube video ID
- title: String - Song title
- duration: Int - Duration in seconds
- thumbnailUrl: String? - Album art URL
- liked: Boolean - Favorite status
- totalPlayTime: Long - Total play time in milliseconds
- inLibrary: Long? - Timestamp when added to library
- explicit: Boolean - Explicit content flag
- isVideo: Boolean - True if music video
- isDownloaded: Boolean - Offline availability
- dateDownload: LocalDateTime? - Download timestamp
- lyricsOffset: Int - Manual lyrics timing offset
- isUploaded: Boolean - User uploaded content

ArtistEntity
------------
- id: String (PRIMARY KEY)
- name: String
- thumbnailUrl: String?

AlbumEntity
-----------
- id: String (PRIMARY KEY)
- title: String
- year: Int?
- thumbnailUrl: String?
- songCount: Int
- duration: Int
- lastUpdateTime: Long
- bookmarkedAt: Long?
- browseId: String?
- description: String?
- isUploaded: Boolean

PlaylistEntity
--------------
- id: String (PRIMARY KEY)
- name: String
- browseId: String?
- bookmarkedAt: Long?
- isEditable: Boolean
- createdAt: Long
- lastUpdateTime: Long

FormatEntity
------------
- id: String (PRIMARY KEY)
- itag: Int - YouTube format identifier
- mimeType: String
- codecs: String
- bitrate: Int
- sampleRate: Int?
- contentLength: Long
- loudnessDb: Float?
- perceptualLoudnessDb: Float?
- playbackUrl: String?

LyricsEntity
------------
- id: String (PRIMARY KEY)

Event
-----
- songId: String

PlayCountEntity
---------------
- songId: String
- year: Int
- month: Int
- dayOfWeek: Int
- day: Int

- count: Int

SearchHistory
-------------
- id: Int (PRIMARY KEY, auto-increment)

Related Tables:
- SongArtistMap: Many-to-many song-artist relationship
- SongAlbumMap: Song-album relationship with track index
- AlbumArtistMap: Album-artist relationship

  - Show waiting indicator

Playback Errors:

  - Auto-skip to next song on error
  - Pause after too many errors
  - User intervention required after pause

Stream URL Expiry:
  - Cache URLs with expiry timestamp
  - Auto-refresh expired URLs
  - Retry with fresh URL on failure
